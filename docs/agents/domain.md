# Domain documentation

Read `.agents/product-marketing.md` for approved service definitions, evidence, offers, and voice. Read the applicable decision record or brief under `docs/` before changing an offer or page hierarchy.

For the September 2026 evidence-led positioning work, start with
[the positioning source map](../positioning/source-map.md). It connects the
approved context, current copy draft, proof and local customer research.

For website copy, apply the [customer-copy correction](../positioning/customer-copy-review-2026-09-14.md).
Lead heroes and service introductions with the visitor's task or benefit,
then explain the service. Reserve founder background for relevant proof and
the working relationship. An opening list of what Matt builds or handles
does not satisfy this direction.
For website and growth work, make expertise part of the value: experienced
strategy, current tools and sound practice applied to the customer's business.
Convenience alone does not explain why the customer should hire Matt.
Give each service-page section a distinct purpose. Avoid repeating the same
capabilities across multiple sections, and keep supporting FAQ answers concise.

If a future task needs a shared glossary, maintain `CONTEXT.md`. Record hard-to-reverse domain decisions under `docs/adr/`. Create these only when the work produces a real decision; their absence does not block routine fixes.
